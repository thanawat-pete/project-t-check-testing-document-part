# SPRS-Test-Cases Full Specification (สรุป)

เอกสารสรุปกรณีทดสอบ Robot Framework ของระบบ T-check ในรูปแบบอ่านง่าย โดยคงหัวข้อสำคัญตามเอกสารฉบับเต็ม ได้แก่ รหัส/ชื่อเคส, อ้างอิง, ความสำคัญ/ประเภท, เงื่อนไขตั้งต้น, ขั้นตอน, ข้อมูลทดสอบ, ผลคาดหวัง, ผลจริง และสถานะ

> **ขอบเขต:** สรุปตาม test cases ที่มีอยู่ใน `robot/tests/` ไม่ได้ขยายความสามารถเกินสิ่งที่ Robot ตรวจจริง ค่าอ้างอิง US/UC และประเภท/ความสำคัญนำมาจาก [เอกสารฉบับเต็ม V2](./SPRS-Test-Cases%20Full%20Specification%20(V2).md) เฉพาะรายการที่พบรหัสตรงกัน หากไม่พบจะระบุว่า “ไม่ระบุ”
>
> **ผลล่าสุดที่อ้างอิง:** Robot output สร้างเมื่อ 12 ตุลาคม 2026 เวลา 14:47 — **20 ผ่าน, 0 ล้มเหลว, 0 ข้าม** ดูหลักฐานที่ [output.xml](../robot/results/output.xml) ผล PASS หมายถึงขั้นตอนและ assertion ที่เขียนไว้ใน Robot ผ่าน ไม่ได้แปลว่าฟังก์ชันที่ไม่มี assertion ถูกยืนยันครบถ้วน

### กลุ่ม 7 — การแยกข้อมูลผู้ใช้

#### TC-SEC-001 — User B ไม่เห็นเอกสารเฉพาะของ User A

| หัวข้อ | รายละเอียด |
|---|---|
| อ้างอิง (US/UC) | US-DOC-020 |
| ความสำคัญ / ประเภท | วิกฤต / Security & Isolation (IDOR Protection) |
| เงื่อนไขตั้งต้น | มีบัญชีทดสอบ User A และ User B; ระบบอนุญาตให้เข้าสู่ระบบทั้งสองบัญชี |
| ขั้นตอน | 1. ล็อกอินเป็น A  2. สร้างเอกสารชื่อสุ่มเฉพาะและรอ `บันทึกแล้ว`  3. ตรวจว่าชื่ออยู่ในคลัง A  4. เปิด context ใหม่และล็อกอินเป็น B  5. ตรวจเนื้อหาหน้าหลักว่าไม่มีชื่อเอกสารดังกล่าว |
| ข้อมูลทดสอบ | ชื่อเอกสารมี prefix `TC-SEC-001-` และ UUID; ข้อมูลล็อกอินอ่านจาก environment configuration ไม่แสดงในเอกสารนี้ |
| ผลที่คาดหวัง | เอกสารที่สร้างโดย A ไม่ปรากฏในคลังของ B |
| ผลจริง | เอกสารปรากฏในคลัง A และไม่พบชื่อเอกสารนั้นในเนื้อหาหน้าหลักของ B |
| สถานะ | **ผ่าน** — ยืนยันการไม่แสดงชื่อเอกสารนี้ในหน้าคลังของ B ตามการตรวจที่กำหนด |

## ข้อจำกัดและแนวทางอ่านผล

- เคส `Guest User Should Be Redirected To Editor` และ TC-GST-001 ตรวจเส้นทาง Guest ไป Editor ซ้ำกัน โดยเคสแรกไม่มีรหัส TC ใน Robot ส่วน TC-GST-001 มีรหัสอ้างอิงจาก V2
- ผลทดสอบของ Robot ล่าสุดไม่ควรนำไปปะปนกับผลจริงเก่าที่เขียนในเอกสาร V2
- TC-SCH-001 ตรวจค่าที่ป้อนในช่องค้นหา ไม่ได้ตรวจผลกรองรายการเอกสาร
- TC-SRT-001 ตรวจการเลือกตัวเลือกเรียงลำดับ ไม่ได้ตรวจลำดับการ์ดจริง
- TC-AI-002 ตรวจการคลิกปุ่มตรวจสอบ ไม่ได้ตรวจผลตอบกลับจาก AI
- TC-IMP-001 ตรวจเพียงว่ามีข้อความ `Import`; TC-EXP-001 มีการคลิกแบบมีเงื่อนไขและไม่ยืนยันการดาวน์โหลด
- TC-TRH-001, TC-TRH-003 และ TC-TRH-004 ข้ามการกระทำหลักภายในเคสได้เมื่อไม่พบปุ่มที่เกี่ยวข้อง แม้ผลรวมของ Robot จะแสดง PASS
- หากต้องการยืนยันพฤติกรรมเหล่านี้อย่างเต็มรูปแบบ ควรเพิ่มการเตรียมข้อมูลทดสอบเฉพาะเคสและ assertion หลังการกระทำ
