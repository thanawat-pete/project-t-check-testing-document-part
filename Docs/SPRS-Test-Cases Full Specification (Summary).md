# SPRS-Test-Cases Full Specification (สรุป)

เอกสารสรุปกรณีทดสอบ Playwright ของระบบ T-check ในรูปแบบอ่านง่าย โดยคงหัวข้อสำคัญตามเอกสารฉบับเต็ม ได้แก่ รหัส/ชื่อเคส, อ้างอิง, ความสำคัญ/ประเภท, เงื่อนไขตั้งต้น, ขั้นตอน, ข้อมูลทดสอบ, ผลคาดหวัง, สิ่งที่ Playwright ตรวจ และสถานะ

> **ขอบเขต:** สรุปตาม test cases ที่มีอยู่ใน `playwright/tests/` ค่าอ้างอิง US/UC และประเภท/ความสำคัญนำมาจาก [เอกสารฉบับเต็ม V2](./SPRS-Test-Cases%20Full%20Specification%20(V2).md) เฉพาะรายการที่พบรหัสตรงกัน หากไม่พบจะระบุว่า “ไม่ระบุ”
>
> **สถานะการรัน:** เอกสารนี้อธิบายชุด Playwright ที่มีอยู่ แต่ไม่มีรายงาน Playwright ล่าสุดที่ยืนยันผลรัน จึงไม่ใช้ผล Robot 20/20 จาก [output.xml](../robot/results/output.xml) มาอ้างแทน Playwright สถานะด้านล่างจึงระบุว่า “ยังไม่มีหลักฐานผลรัน Playwright” จนกว่าจะรัน `npm test` และเก็บผลรายงาน
>
> **หมายเหตุ:** การมี test case ในไฟล์ Playwright ไม่ได้แปลว่ามีการตรวจยืนยันพฤติกรรมครบทุกข้อ บางเคสไม่มี assertion, ข้าม action เมื่อ element ไม่ปรากฏ หรือถูก skip เมื่อไม่มีข้อมูลบัญชีทดสอบ
>
> **แหล่ง test:** [playwright/tests](../playwright/tests/)

### กลุ่ม 7 — การแยกข้อมูลผู้ใช้

#### TC-SEC-001 — User B ไม่เห็นเอกสารเฉพาะของ User A

| หัวข้อ | รายละเอียด |
|---|---|
| อ้างอิง (US/UC) | US-DOC-020 |
| ความสำคัญ / ประเภท | วิกฤต / Security & Isolation (IDOR Protection) |
| เงื่อนไขตั้งต้น | มีบัญชีทดสอบ User A และ User B; ระบบอนุญาตให้เข้าสู่ระบบทั้งสองบัญชี |
| ขั้นตอน | 1. หากไม่มี credentials ของ User B ให้ Playwright skip เคส  2. ล็อกอินเป็น A ใน context แยก สร้างเอกสารชื่อเฉพาะ และตรวจว่าชื่ออยู่ในคลัง A  3. ล็อกอินเป็น B ใน context อีกชุด  4. ตรวจว่า heading ชื่อเอกสารของ A มีจำนวน 0 |
| ข้อมูลทดสอบ | ชื่อเอกสารมี prefix `TC-SEC-001-` และ timestamp; credentials ของ B อ่านจาก environment variables โดยไม่แสดงในเอกสารนี้ |
| ผลที่คาดหวัง | เอกสารที่สร้างโดย A ไม่ปรากฏในคลังของ B |
| สิ่งที่ Playwright ตรวจ | ยืนยันชื่อในคลัง A และตรวจว่า User B ไม่มี heading ที่มีชื่อนั้น; หากไม่มี credentials ของ B เคสถูก skip |
| สถานะ | **ยังไม่มีหลักฐานผลรัน Playwright** — ผลขึ้นกับการกำหนด `TEST_USER_B_USERNAME` และ `TEST_USER_B_PASSWORD` |

## ข้อจำกัดและแนวทางอ่านผล

- เคส `Guest user should be redirected...` และ TC-GST-001 ตรวจการเปลี่ยนเส้นทางซ้ำกัน
- ผล Robot 20/20 ที่มีอยู่เป็นหลักฐานของ Robot เท่านั้น ไม่ใช่ผลของ `npm test`
- TC-SCH-001 ตรวจค่าที่ป้อนในช่องค้นหา ไม่ได้ตรวจผลกรองรายการเอกสาร
- TC-SRT-001 ตรวจการเลือกตัวเลือกเรียงลำดับ ไม่ได้ตรวจลำดับการ์ดจริง
- TC-AI-002 และ TC-TON-001 ใช้ action แบบมีเงื่อนไข; TC-TON-001 ไม่ได้เลือก Strict/Casual ใน Playwright ปัจจุบัน
- TC-IMP-001 ไม่มี assertion หรือการกระทำ Import; TC-EXP-001 คลิกแบบมีเงื่อนไขและไม่ยืนยัน modal/ไฟล์
- TC-TRH-001, TC-TRH-003 และ TC-TRH-004 ข้ามการกระทำหลักได้เมื่อไม่พบปุ่ม โดยไม่มี assertion ยืนยันผลหลังทำงาน
- TC-SEC-001 ถูก skip เมื่อไม่มี credentials ของ User B; จึงต้องตรวจผลรายงาน Playwright ว่า skipped หรือ passed ทุกครั้งที่รัน
- หากต้องการยืนยันพฤติกรรมเหล่านี้อย่างเต็มรูปแบบ ควรเพิ่มการเตรียมข้อมูลทดสอบเฉพาะเคสและ assertion หลังการกระทำ
