# SPRS-Test-Cases Full Specification (สรุป)

เอกสารสรุปกรณีทดสอบ Playwright ของระบบ T-check ในรูปแบบอ่านง่าย โดยคงหัวข้อสำคัญตามเอกสารฉบับเต็ม ได้แก่ รหัส/ชื่อเคส, อ้างอิง, ความสำคัญ/ประเภท, เงื่อนไขตั้งต้น, ขั้นตอน, ข้อมูลทดสอบ, ผลคาดหวัง, สิ่งที่ Playwright ตรวจ และสถานะ

> **ขอบเขต:** สรุปตาม test cases ที่มีอยู่ใน `playwright/tests/` ค่าอ้างอิง US/UC และประเภท/ความสำคัญนำมาจาก [เอกสารฉบับเต็ม V2](./SPRS-Test-Cases%20Full%20Specification%20(V2).md) เฉพาะรายการที่พบรหัสตรงกัน หากไม่พบจะระบุว่า “ไม่ระบุ”
>
> **สถานะการรัน:** ผล Robot 20/20 จาก [output.xml](../robot/results/output.xml) ไม่ใช้แทน Playwright. Playwright Import/Export ผ่าน 2 เคส, Trash Lifecycle ผ่าน 4 เคส, Document List/Search/Sort ผ่าน 3 เคส และ Multi-Tenancy/IDOR ผ่าน 1 เคส เมื่อ 20 ต.ค. 2026; อีก 10 เคสยังไม่มีหลักฐานผลรัน Playwright ในรอบนี้
>
> **หมายเหตุ:** การมี test case ในไฟล์ Playwright ไม่ได้แปลว่ามีการตรวจยืนยันพฤติกรรมครบทุกข้อ บางเคสไม่มี assertion, ข้าม action เมื่อ element ไม่ปรากฏ หรือถูก skip เมื่อไม่มีข้อมูลบัญชีทดสอบ
>
> **แหล่ง test:** [playwright/tests](../playwright/tests/)

### กลุ่ม 7 — การแยกข้อมูลผู้ใช้

#### TC-SEC-001 — User B ไม่เห็นเอกสารเฉพาะของ User A

| หัวข้อ | รายละเอียด |
|---|---|
| อ้างอิง (US/UC) | US-DOC-020 |
| ความสำคัญ / ประเภท | วิกฤต / Security & Isolation (IDOR Protection) |
| เงื่อนไขตั้งต้น | มีบัญชีทดสอบ User A และ User B; ระบบอนุญาตให้เข้าสู่ระบบทั้งสองบัญชี |
| ขั้นตอน | 1. หากไม่มี credentials ของ User B ให้ Playwright skip เคส  2. ล็อกอิน A ใน context แยก สร้างเอกสารพร้อมเนื้อหาเฉพาะ และยืนยันจากรายการ API/UI ของ A  3. ล็อกอิน B ในอีก context และยืนยันว่าเป็นคนละ identity  4. ตรวจรายการ API/UI ของ B ว่าไม่มีเอกสาร A  5. เปิด URL เอกสาร A โดยตรงในฐานะ B และตรวจ HTTP 403  6. ลบถาวรเฉพาะเอกสารที่เคสสร้าง |
| ข้อมูลทดสอบ | ชื่อและเนื้อหาใช้ prefix `TC-SEC-001-`/`Private document content` พร้อม timestamp; credentials ของ B อ่านจาก environment variables โดยไม่แสดงในเอกสารนี้ |
| ผลที่คาดหวัง | เอกสาร A ไม่ปรากฏในคลัง B; การเรียกอ่านเอกสาร A ด้วยบัญชี B ถูกปฏิเสธด้วย HTTP 403; teardown ลบเฉพาะข้อมูลที่สร้าง |
| สิ่งที่ Playwright ตรวจ | ยืนยัน identity ของ A/B แตกต่างกัน, ตรวจ id/title จาก response `/api/docs` และ heading, เปิด URL `/docs/editor/:id` จาก B และยืนยัน API GET `/api/docs/:id` ตอบ 403; ตรวจว่า title/content ไม่ปรากฏและยืนยันผล cleanup |
| สถานะ | **ผ่าน** — Playwright 20 ต.ค. 2026, 1/1; บัญชี B ใช้ credentials จาก environment โดยไม่พิมพ์ค่าออก |
